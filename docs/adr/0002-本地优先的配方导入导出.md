# 本地优先的配方导入导出

状态：accepted

当前阶段不接入云开发，自定义配方作为当前设备上的私人内容保存；跨设备迁移和轻量传递通过单条配方导入码完成。我们选择这个方向，是因为当前产品还没有账号、云同步、公开分享和内容审核需求，而本地保存加导入导出能满足自定义配方迁移的核心场景，并避免过早引入云端身份、权限和同步复杂度。

## Consequences

配方导入码应承载单条自定义配方的可制作信息快照，并包含版本标识；V1 编码采用 `COCKTAIL_V1:<Base64(JSON)>`，JSON 使用可读字段名而不是短码字段。其中制作步骤只承载按顺序排列的步骤说明文本，成分和步骤都最多 30 个。当前只以复制和粘贴文本的方式传递配方导入码，不做文件导入导出；二维码或小程序码可在未来作为呈现形式评估。导入时不校验可信来源，但必须校验版本、格式和内容合法性，并复用添加配方草稿的内容校验口径；校验通过后先生成导入预览，由用户确认后再保存为当前设备上的自定义配方，且不得覆盖已有配方。未来如果接入云开发或社交分享链接，应作为新的产品和架构决策重新讨论。
